# Hosting the static demo on Netlify

Netlify hosts a **static demo**: the frontend is exported to plain HTML/CSS/JS (`frontend/out`) and serves only the
pre-computed Showcase from bundled files. The Python backend (camera analysis, potentiostat import, database, ML)
cannot run on Netlify; every other page explains that it needs the local app. No Netlify Next.js runtime is used.

## Deploy
1. Netlify → *Add new project → Import an existing project → GitHub* → `wetcor-AI`, branch `main`.
2. Settings (these are also in `netlify.toml`; typing them in the UI is fine):
   * **Base directory:** `frontend`
   * **Build command:** `npm run build`
   * **Publish directory:** `out`   (not `.next`)
   * Environment variables are optional: static mode switches on by itself on Netlify (`NETLIFY=true`).
3. Deploy. Both `/` and `/showcase` show the showcase.
4. Check: `https://<site>.netlify.app/showcase-static/snapshot.json` shows JSON.

## What is served
`frontend/public/showcase-static/` — `snapshot.json`, `source.png`, `overlay.png`, `report.html`, generated by the real
backend code:

```powershell
backend\.venv\Scripts\python scripts\export_static_showcase.py
```
Re-run it (and commit the files) after changing `data/showcase/` or the analysis code.

## Local app is unaffected
Static mode is on only when `NEXT_PUBLIC_STATIC_DEMO=1` or `NETLIFY=true`; `setup-windows.ps1` / `run-local.ps1` build the
normal app. To try the export locally: `cd frontend; $env:NEXT_PUBLIC_STATIC_DEMO=1; npm run build` (output in `out/`),
then delete `out` and `.next` before running `run-local.ps1`.

## Limits
* No live camera analysis, uploads, database, ML or new reports on the hosted site.
* Showcase electrochemistry is synthetic; the droplet image is a public stand-in (see `data/showcase/README.md`).
